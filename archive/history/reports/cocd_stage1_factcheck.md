### 1.3 真实样本的有效权重（为什么"梯度总量之比"不能由 batch 推）

`land_loss` 的 BCE 是**对整个 batch 的所有像素取均值**，dice 是逐样本取均值再 `.mean()`
（`losses/landslide_cocd.py:4-7`）。因此：

```
loss(batch) = (1/B) · Σ_{s∈batch} ℓ_s ,        ℓ_合成样本 ≡ 0   （见 §2）
```

每个真实样本每 epoch **恰好出现一次**（spec 中 mode 0 每行一个），所以

```
每 epoch 线性梯度总和 = (1/B) · Σ_{真实样本} ∇ℓ      ⇒ 比值恰好 = 8/2 = 4.000
每 epoch 真实样本当量 = 1233/B = 616.5 (Teacher) vs 154.125 (Student)
```

实测印证（`stage1_factcheck_loader.csv`）：`Σ(r/B)` 每 epoch = **616.500** vs **154.125**，
比值 **4.000**。

**但直接说"Teacher 的梯度总量是学生的 4 倍"是错的**：AdamW 的每步位移
`lr·m̂/(√v̂+ε)` 与梯度尺度无关，线性求和不会累积。真正在两侧不同的是
**更新次数 1,850 : 463 = 3.996**，以及**零梯度滑行步的占比**（§1.4）。

## 2. 零梯度：作用域、机制与逐类甄别

### 2.1 逐类甄别（本轮指定要区分的六类）

| 类别 | 是否存在 | 证据 |
|---|---|---|
| 有效**像素**为空 | **是**（合成样本 `y≡0`），但像素总数仍是满的 16,384/样本 | `21:45` `y=land if mode==0 else np.zeros_like(land)` |
| batch 被跳过 | **否** | 两脚本内无 `continue` / `if ...sum()==0` / `drop_last` |
| 分支被关闭 | **否** | Teacher 恒求和 3 个头 ×2 方向；Student 恒求和 z4/z34；无短路 |
| `.grad is None` | **否** | Teacher 202/202、R3 210/210 全部是**零张量**，`None` 计数为 0 |
| **恰好为零的梯度** | **是，且是整个模型**（对合成 batch 而言） | 见 2.2 |
| 混合精度跳步 | **不适用** | 无 `autocast` / `GradScaler`，不存在 fp16 溢出跳步 |

### 2.2 机制：合成样本的概率**恰好**为 0，两点同时归零

实测（合成 batch，Teacher 六个头全部一样）：

```
sigmoid(logits).max() = 0.000e+00       frac(p == 0) = 1.0000
loss = 0.0（精确）                      202/202 参数 grad 为零张量，0 个 None
```

因为 `p ≡ 0` 时：BCE 项 `= -log(1-0) = 0`；dice 项分子 `= EPS`、分母 `= EPS`，
`d = 1 - 1 = 0`，且 `∂d/∂p = 0`（`t=0`）。**两项的值与导数同时为零**，所以这是一个
**精确不动点**：零梯度使 `p` 永远停在 0，S0 的饱和状态被永久继承。

### 2.3 稀释：合成样本对真实梯度只做 1/B 缩放（eval 模式实测）

| 测例 | loss | 比值 |
|---|---:|---:|
| `[真实]` | 0.03331147 | — |
| `[真实, 合成]` | 0.01665573 | **0.49999978**（= 1/2，合成项精确贡献 0） |
| `[合成]` | **0.000e+00** | — |

> train 模式下 DropPath/StochasticDepth 会让同一样本的两次前向不可比（同一对 batch
> 实测比值 0.5277，纯属随机性），所以该比值必须在 eval 下测。上表是 eval 结果。

### 2.4 结构上恒为零的 10 个参数（与 batch 无关）

每个 `Correction`（Teacher 的 `a3/a4`、Student R2/R3 的 `op3/op4`）有 5 个参数在任何
真实 batch 上恒为零梯度：

```
{net.0.weight, net.0.bias, net.2.weight, net.2.bias, net.4.bias}   × {a3, a4} = 10
```

- `net.0/net.2` 是**初始化时**的零梯度：最后一层 `net.4.weight` 零初始化 ⇒ 上游链式梯度为 0；
  一旦 `net.4.weight` 变成非零（第 2 步起）它们就活了。**实测印证**：训练后
  `teacher.pt` 里 `a3.net.0.weight = 0.2597`、`a3.net.2.weight = 0.2985`、
  `a3.net.4.weight = 0.1961`（全部非零）。
- `net.4.bias` 是**代数上死掉**的：`Ω = op(cat(a,c)) − op(cat(a,0))`，末层 bias 在两项里相同、
  相减精确抵消 ⇒ `∂Ω/∂b ≡ 0`。**实测印证**：训练 50 epoch 之后，
  `teacher.pt` / `teacher_T2a.pt` / `R2_seed42.pt` / `R3_seed42.pt` 里这 4 个 bias 仍是
  `max|b| = 0.000e+00`。
- 该集合在 40 次重复中稳定为 10（n=2/8 的 batch）；**唯一边动的是随机成分**：n=1 的 batch 下
  40 次里有 2 次变成 19（多出 `backbone.features.7.1` 那 9 个张量，是该 CNBlock 的
  `stochastic_depth` 遮掉整条残差支路）。所以"零梯度参数个数"不是结构常数，
  **结构常数是上面那 10 个 Correction 张量**。

### 2.5 学生侧：选择性臂同样惰性，**DIS2-port 不是**

| 模型 | 合成-only batch 的 loss | 梯度作用域 |
|---|---|---|
| Teacher（T2a 目标） | seg = **0.0** | 202/202 全零 |
| Student R1（`kd='gain'`） | seg = 0.0，kd = **0.0**（`w>0` 占比 0.0000） | 202/202 全零 |
| Student R3（`kd='gain'`） | seg = 0.0，kd = **0.0**（`w>0` 占比 0.0000） | 210/210 全零 |
| **Student DIS2（`kd='dis2'`）** | `kd_dis2` = **0.001069**（syn1）/ 0.002923（syn2） | **192/202 非零** |

原因：选择性臂的权重 `w = gain·protect`，而 `gain = (e0−et)/(e0+EPS)` 在 `p0=p34=0` 时
分子分母同时为 0 ⇒ `w ≡ 0`；DIS2 的 `dis2_multilevel_kd` **没有逐像素权重**，
其四级池化 L2 + penultimate L2 + logits KL 直接吃整批样本。

> **这是基线公平性的一条事实**：2/3 的样本只被 DIS2 规则消费，Ours 族全部丢掉。
> 它不改动任何结果，但写进论文时必须披露。

## 3. 路径事实

| 问题 | 答案 | 证据 |
|---|---|---|
| `z0/z4/z34` 是否共享同一解码与预测路径 | **是同一个 decoder，不是三个头**。`decoder.backbone is backbone`，共享 `l2` + `head`（`Conv2d(128,64,3)+GELU+Conv2d(64,1,1)`，**73,857 参数 = 全模型 0.2626%**），三个读数只是用不同的 `(p3,p4)` 各调一次 `decode` | `models/landslide_cocd_v2.py:85-111` |
| 关闭反轨 correction 是否回到 self | **r≡0 时精确回到 self**：`states(ft,None,None)` 三个张量逐位相同（`torch.equal` 为真） | 实测 `states_none_all_identical = true` |
| 那么"把反轨输入置零"等于关闭吗 | **不等**。Ω 的零参照在**状态层**（`op(cat(a,0))`），不是图像层；`l2–l5` 是带 bias 的 1×1 conv（`l3.bias is not None = True`），零图像仍给出 `‖p3c‖ = 29.85`（真实反轨为 585.99），`‖r‖max = 0.1559 ≠ 0`，三个头不再相同 | `46: [2]` |
| P4 修正是否实际进入 P3 | **是**。`p3' = l3(c3) + up(p4 + r4)`，传播量 L2 = **66.33**；单独打开 r4 就改变输出（`Δ(z4,z0)max = 28.13`），单独打开 r3 再改（`Δ(z34,z4)max = 72.63`） | `44: C` 实测 |
| 但 r3 是在哪个状态上算的 | **在未修正的 P3 上算**：`r3 = a3(cat(p3t,p3c)) − a3(cat(p3t,0))`，`p3t` 来自 `pyramid(ft)`；随后被加到**已被 P4 修正过的** P3 状态上。这个不对称正是 R3 学生改掉的东西（R3 的 `drive3 = a3` 已是传播后状态） | `v2:137-139`、`v2:110`、`v3:254` |
| Student 是否继承 Teacher 的修正变换 | **只有 R2/R3（含 R3g）**：`op3/op4 ← a3/a4` **逐位相同**（`torch.equal` 全键为真）。**R0/R1/DIS2-port 没有 Ω**（DIS2-port 是 variant R1，只有自己新初始化的 `q3/q4`）。继承的算子**不冻结**（`op3.requires_grad = True`），50 epoch 后相对 L2 漂移 **R3: 0.311 / 0.285，R2: 0.227 / 0.204** | `44: D`、`45` 无、checkpoint 实测 |
| 继承算子第一步有没有梯度 | **恰好没有**。driver 末层零初始化 ⇒ `r = Ω(op,a,0) = 0` 精确 ⇒ `∂L/∂op ≡ 0`。实测：更新 #1 时 `op3.net.*`/`op4.net.*` 的 `|grad|max = 0.000e+00`，而 `d3.net.2.weight = 2.755e-04`（driver 末层拿到梯度）→ 更新 #1 后 driver 末层变为 `1.0e-04`，`|r3|max` 变 2.19e-02 → 更新 #2 起 Ω 开始拿到非零梯度（2.5e-5 / 4.3e-5 / 3.4e-5） | `46: [3]` |

## 4. 计划中的 `L_corr` / `L_delta`：公式、张量与实现状态

**实现状态：两者都尚未实现。** 全仓 grep 无 `L_corr` / `L_delta` / `delta_loss` / `SmoothL1`。
唯一存在的相关项是 V1 的 `correction_loss`（`losses/landslide_cocd.py:12-15`，余弦距离 × 几何门），
它只被遗留的 V1 路径 `scripts/21:103` 使用；**R1/R2/R3/DIS2-port 的损失里没有任何一项要求
`r ≈ r_T`**——这是当前结构阶与"修正层蒸馏"之间的真实缺口。

### 4.1 `L_corr = SmoothL1(norm(R_S), stopgrad(norm(R_T)))`

| 项 | 张量 | 现状 |
|---|---|---|
| `R_S` | R1：`(q3(p3), q4(p4))`；R2/R3：`taps['r'] = (r3, r4)`，即 Ω 输出 | 已存在（`forward_taps` 返回 `r`） |
| `R_T` | Teacher `taps['r']`，`(r3_T, r4_T)`，**已 detach** | 已存在（`from_features_taps` 返回 `r`） |
| 形状 | r3: `(B,128,16,16)`，r4: `(B,128,8,8)`（P3=1/8、P4=1/16 of 128） | 两侧完全对齐 |
| 归一化维度 | `norm(·)` 需明确是通道维（`dim=1`） | 未定义 |
| 梯度流向 | 只流向学生（教师已 detach）；经 `r3/r4 → p3/p4 → decode` 同时进入 backbone 与修正模块 | — |

**三处必须先定、否则会做成另一个东西：**

1. 两侧都做了 `norm` ⇒ 该式只匹配**方向**、不匹配**幅值**，与 V1 `correction_loss` 同一性质。
   若本意是"修正量本身要对齐"，需要去掉 norm 或加尺度项。
2. **R0 上没有定义**：R0 无修正模块，`r ≡ 0`，该项退化为常数 `‖norm(R_T)‖`，梯度恒为 0。
   要么对 R0 关闭该项，要么 R0 不能进这个比较。
3. R1 的 `R_S` 是自由残差头输出，R2/R3 的 `R_S` 是 Ω 输出——同一公式在两个臂上量的是不同对象，
   跨臂比较前要说明。

### 4.2 `L_delta = SmoothL1(Δz_S, stopgrad(Δz_T))`

| 项 | 张量 | 现状 |
|---|---|---|
| `Δz_S`（r3 的效果） | `z34_S − z4_S`，`(B,1,128,128)` | 已存在（`taps['z34']`、`taps['z4']`） |
| `Δz_T` | `z34_T − z4_T`，`(B,1,128,128)`，已 detach | 已存在（`t['z34']`、`t['z4']`） |
| `Δz_S`（r4 的效果） | 需要 `z4_S − z0_S`，但 **学生的 `forward_taps` 不返回 `z0`** | **缺一个张量**：要在学生里加一次 `decoder.decode(c2, p3, p4)`（1 行）才拿得到 |
| 梯度流向 | 只流向学生；经两次 `decode` 同时进入 backbone 与修正模块 | — |
| R0 | `z4 = z34 = z` ⇒ `Δz_S ≡ 0`，同 4.1 第 2 条 | — |

负类基数 4,181,630，self 的误报率 4.05%，R3 3.61%，DIS2-port 3.60%。）

### 5.3 从这张表能读出的三条结论

1. **学生并没有"学会反轨机制"，而是走到了同一个工作点。** R3 只找回 52.3% 的反轨专属正像素，
   却把 FPcut 那批像素的 61.4% 一起压掉；它的净收益来自**更激进的消误检**——在
   "self 会误报的负像素"上，学生把误报率从 100% 压到 **77.5%**，比反轨自己的 84.3% 还狠。
2. **没有在别处增加误检。** U 之外的 FP：R3 比 self 少 **1,994**、DIS2-port 少 2,376；
   FP 总数分别降 10.8% / 11.0%。代价在召回：FN 总数由 self 的 18,624 升到 18,662 / 19,070
   （U 外召回 0.9540 → 0.9458 / 0.9454）。
3. **几何加权确实把蒸馏推向了反轨位置，但没换来分数。** R3g 的 TPgain 找回率是学生里最高的
   **0.568**（比 R3 高 4.5 pp），同时携带的 FPadd 也最高（0.381）；它的总 IoU 仍低于 R3。
   这是对 R3g 诊断的独立确认：**方向对上了，通道不够。**

### 5.4 区域细节里的一条必须记住的事实
