## 一、项目与数据（一次性给足）

- 任务：SAR 快速滑坡变化检测（rapid single-orbit landslide change detection）。灾后第一景 SAR 到达后就要出图，
  因此**部署时只有一个轨道可用**，但训练时可以借助另一轨道。
- 数据：Haiti，按**空间位置**划分，1,233 train / 137 内部验证（从 train 按 seed 42 抽 10%）/ 343 test，
  共 1,713 个位置。**同一位置的 ASC/DESC 与 pre/post 四张栅格同进同出，绝不跨 split。**
- 输入：`[VV_pre, VH_pre, VV_post, VH_post, OrbitID]`，128×128，5 通道。两条轨道 ASC / DESC。
- 训练样本：每个 train 位置 6 例 —— 2 轨道 × 3 种时间模式：
  `pre→post`（GT = 滑坡）、`pre→pre`（GT = 0）、`post→post`（GT = 0）。
  后两者是**合成的 no-change 负样本增广**，用来防止模型仅凭单张 post 图判断。
  每 epoch 单轨样本 7,398 = 真实 2,466（1,233 ASC + 1,233 DESC）+ pre/pre 2,466 + post/post 2,466。
- 验证/测试：**不生成合成对**，只评真实 `pre→post`。test 共 686 个单轨案例（343 ASC + 343 DESC）。
- 评价分区：按"目标轨是否失真 / 反轨是否失真"划成 G00（都好）/ G01（反轨坏）/ G10（目标轨坏、反轨好）/ G11（都坏）。
  **G10 是重点**——它是"单轨信息损失"最严重、也是反轨唯一能救场的位置。
- 统一训练协议（已冻结）：Adam、lr 5e-5 **恒定、无 scheduler**、**physical batch 16**（实测可行，无需梯度累积）、
  **普通 BCE（无 pos_weight、无 Dice、无 Focal）**、**最多 20 epoch**、每 epoch 验证、**early stop patience 3**、
  按 **validation AUPRC** 选 best checkpoint、阈值在 **validation 上按 F1 最大搜索后冻结**再用于 test
  （AUPRC 无阈值；**绝不在 test 上调阈值或选模型**）、**raw / no-mask**（几何 mask 只用于评价分区，绝不进训练）。
- 一条必须先知道的训练事实：合成样本的 GT 恒为 0，而模型在这些样本上的输出概率**精确为 0**，
  导致 BCE 与 Dice 的**值与导数同时为零** ⇒ 这 2/3 样本**从头到尾不产生任何梯度**（是整个模型，不是某个分支）。
  实测：batch 2 且 shuffle 时约 **44.5%** 的 optimizer step 是"零梯度滑行步"，batch 16 时约 **3.9%**。

## 二、四个对象：定位、作用、彼此关系

这里有**两条正交的轴**加**一条结构阶梯**，请先把它们分开，再看交叉。

### 轴一：信息权限 —— Teacher（教师）vs Student（学生）

**Teacher = 唯一允许同时使用两条轨道的模型。**
- 它的调用形式是 `forward_pair(asc, desc)`，一次前向同时给出两个方向的样本：
  ASC 目标配 DESC 反轨、DESC 目标配 ASC 反轨。这是它的全部"特权"。
- 结构：共享 ConvNeXt-Tiny + FPN 骨干；两个修正算子 `a3/a4`（各 256→128 的 1×1-3×3-1×1 卷积，末层零初始化），
  输入是 `[目标状态, 反轨状态]`，输出逐尺度修正量。
- 关键构造 Ω：`Ω(a, c) = op(cat(a, c)) − op(cat(a, 0))`。
  即**减去"反轨为零"时的前向**，所以 `Ω(a, 0) ≡ 0` 精确成立。它表达的是"反轨带来的**边际**贡献"，
  而不是把两轨特征融合成一个新特征——这条是整个设计的承重假设。
- 三个读数**共用同一个 decoder**（不是三个头）：`z0` = 未修正自轨；`z4` = 只用 P4 修正、并沿自上而下路径传到 P3；
  `z34` = P3+P4 都修正，**是学生的蒸馏目标，也是选模与部署的读数**。
- 它的作用有二：(1) 作为 privileged-information 模型，提供软目标；(2) 作为 **Ω 算子的供体**。
- 现状：v2 协议下刚从 ImageNet 初始化训起（**不再从旧的单轨 S0 权重暖启**），正在跑。

**Student = 只有一个模型、每次前向只能看到一条轨道。**
- 部署接口就是 `[VV_pre, VH_pre, VV_post, VH_post, OrbitID]`——**哪条灾后轨道先到，就用哪条立即推理**。
  绝不允许训练两个分别对应 ASC / DESC 的独立模型。
- 训练时把两个方向拼成一个 batch（`cat(asc_target, desc_target)`）交给**同一组权重**，因此一个模型同时学两条轨道。
- 结构阶梯（只改"修正量怎么产生"这一件事）：
  - `R0`：无修正（恒等），即**单轨基线**；
  - `R1`：每个尺度一个自由残差头（q3/q4）；
  - `R2`：把 Teacher 的 Ω 算子**继承**过来，再学一个"驱动器"去喂它（驱动器末层零初始化）；
  - `R3`：在 R2 之上，让 P3 的修正由**已经被 P4 修正过的状态**驱动（递进驱动）。
- 重要性质（已实测）：**四种结构在初始化时的修正量都精确为零**（Ω(a,0)=0 或残差头末层零初始化），
  且四种结构的 backbone `state_dict` **逐位相同** ⇒ 所有臂从**同一个未修正函数**出发。
- 注意一个容易被误读的点：R2/R3 的 Ω 是**从训练好的 Teacher 复制**的，这属于**方法定义本身**（"继承修正算子"），
  而**不是** backbone 的暖启；unified 协议下 backbone 对**所有**内部臂都是同一个 ImageNet 初始化。

### 轴二：蒸馏规则 —— "我们的内容" vs "DS 的内容"

两者都作用在**同一个学生族**、读取**同一组 tap**（多尺度修正后特征、penultimate 图、logits、以及学生侧的两个修正量），
差别只在"选择哪些像素"与"匹配什么量"。这是**方法层面的正面比较**。

**我们的内容（Ours）**
- 定位：把"双轨教师看到的、而单轨学生看不到"的东西，用**逐像素选择性**蒸给学生。
- 规则：`w = gain × protect`，其中
  `gain = clamp((e0 − et) / (e0 + eps), 0, 1)`——教师**双轨读数相对其自轨读数**的 BCE 相对改善；
  `protect = 1[et < es]`——学生自己已经比双轨教师好时置零。
  两个因子都 detached，权重不接收梯度。被匹配的量是 T=1 的稳定 Bernoulli KL（`soft_ce − entropy`），
  按前景/背景**平衡均值**聚合（每个类各占一半，不是逐像素均值）。
- 结构化的新项（**本次唯一新增**）：**修正所导致的"决策变化"蒸馏**，记作 `L_Δ`。
  `Δp = σ(z34) − σ(z0)`（即"修正让概率移动了多少"），
  `L_Δ = aggregate( SmoothL1( Δp_student , stopgrad(Δp_teacher) ) )`，聚合方式与上面的 KD 项一致（前景/背景平衡）。
  对应新臂 `R3D = R3 + L_Δ`，而 **`R3` 是它的精确无 Δ 对照**（结构、蒸馏规则、初始化全同）。
- 尚未实现、且**刻意先不做**的：`L_corr`（直接匹配修正向量本身的余弦/方向）。
  理由是：现有损失里**没有任何一项要求学生的修正量 `r` 接近教师的 `r_T`**，这是明显的缺口；
  但一次只加一项，先把"决策变化"这条通道验掉。
- 几何：几何 mask 只用于**评价分区**，不做任何训练加权。此前尝试过的"几何加权蒸馏"（R3g）**已废弃**。

**DS 的内容（DIS2）**
- 定位：一个已发表的外部蒸馏方法（DLKD 家族 / missing-observation 知识蒸馏），我们做的是**逐字移植到我们的骨干上**。
  它回答的问题是"这个外部规则在我们这套结构上能做到什么"，而不是"它的原论文快照能得多少分"。
- 规则（与我们同一组 tap）：① 四个尺度特征各自池化成 token 后做 **L2 归一化 MSE**；
  ② penultimate 图同样处理；③ 单通道 logits 补一个恒定 0 背景通道后做 **T=2 的 KL**；
  ④ 一个**正交项**（让修正量与自己修正的对象尽量不相关）。教师侧一律 detach。
- **与本项目规则的三个结构性差异（都已实测）**：
  1. DIS2 **没有逐像素选择权重**，所以那 2/3 的合成 no-change 样本**对 DIS2 仍然产生梯度**，
     而我们的选择性臂在这些样本上**精确为零**（`w ≡ 0`）。这是一个必须披露的公平性事实。
  2. 在初始状态，无选择权重的 KD（即"vanilla KD"，`w ≡ 1`）量级是选择性 KD 的 **6–7 倍**
     （验证集上 0.62 vs 0.088，因为 `gain` 只在约 12% 像素上活跃）。
  3. 它的**正交项在本数据集上不活跃**：第 1 epoch 0.0019 → 第 2 epoch 0.0001 → 第 3 epoch 起 0.0000 直到结束
     （跨两个独立实现复现，不是实现问题）。

### 四者之间的关系（一句话各自）

- **Teacher 是唯一的信息特权持有者**：它同时生产软目标与 Ω 算子，因此**必须先训练它**，其余蒸馏臂才能开始。
- **Student 是最终交付物**：它永不接触反轨，两条轨道共用同一个模型。
- **Ours 与 DS 是同一学生对上的两种蒸馏规则**：一个是逐像素选择性 + 决策变化，一个是无选择的多层次特征/logit 匹配。
- **受控比较的固定项**（变一个轴、其余全冻）：split、ASC/DESC 构造、三种时间模式、ImageNet 初始化、Adam、
  lr 5e-5 恒定、effective batch 16、普通 BCE、20 epoch、patience 3、validation AUPRC 选模、
  validation 选阈值、raw/no-mask 评价。**唯一的例外是 R2/R3/R3D 继承 Ω**（方法定义，已单独标注为独立字段）。
- **绝对值不可跨协议比较**：旧协议（AdamW 1e-4 / batch 2 与 8 / BCE+Dice / 50 epoch / 从 S0 暖启）下已跑出的
  一套结果必须与本次统一协议下的结果**分开成表**。去掉 backbone 暖启后，同一前向的 seg 初始值从
  0.011（旧链）变成 **0.742**（新链），所以新协议的绝对值会明显更低，这是预期不是故障。

## 五、两个待决策事项（请给出你的判断与理由）

### 待决 A：`L_Δ` 的权重 `lam_delta` 取多少

- **核心分歧**：`lam_delta = 1.0`（"单位权重"、最忠实）时，`L_Δ` 只占 seg 的 0.42%、KD 项的 3.5%，
  **R3D 与 R3 的比较很可能因为"通道权限"而得到零结果，而不是因为想法本身**。
  但反过来，把权重抬到与 KD 项同权（实测需 **25–30**）又可能让一个新项在 20 epoch 内扰动原本的训练。
- **可选方向**：
  (a) 1.0——最保守，接受"即使无效也说明不了任何事"的风险；
  (b) **10**（我倾向）——约为 seg 的 4%、KD 项的 1/4；
  (c) 25–30——与 KD 项**数值份额**持平；
  (d) 改聚合方式（例如只在决策边界附近加权），但这会同时改变项的定义，使 R3/R3D 的对照不再"只差一个权重"；
  (e) 按目标梯度份额自动配平——**我倾向排除**：整批残差为零时该类自动配平会退化到钳位下界。
- **需要我做的判断**：这里的"份额"是**数值份额**，不等于**梯度份额**；一个残差很小的项，其二次型梯度也相应很小。
  所以真正的选择是"要不要让 `L_Δ` 拿到与 KD 项同级的**话语权**"（→25–30），
  还是"它只作为一次轻推、不允许扰动 seg 目标"（→10 或更小）。
  另外，20 epoch 之内没有第二轮调参的余地，所以**权重必须在开跑前定死**，而唯一读数只能是 R3 vs R3D。

### 待决 B：Teacher 跑完后要不要自动接着跑其余四条臂

- **核心分歧**：Teacher 的任务**更难**（两轨 + 修正），却和所有臂一样只有 20 epoch / lr 5e-5 / ImageNet 起步 / 普通 BCE。
  如果 Teacher 的验证 AUPRC **不高于单轨基线 SO**，那么"教师携带可蒸馏的额外信息"这个前提**没有被建立**，
  后面四条臂（约 4 小时）就是在为一个未经验证的前提跑比较。
- **可选方向**：
  (a) 全部链式跑完（Teacher → SO → VKD → DIS2 → R3 → R3D，约 5 小时），一次性看整张表；
  (b) **先跑 SO（约 1 小时），用"同 epoch 下的 Teacher vs SO"决定是否继续**（我倾向）；
  (c) 质疑判据本身——"Teacher 必须强于 SO"是否是正确的门槛？旧协议下 Teacher 的优势是在**双轨读数**上、
  且是 50 epoch + S0 暖启测出来的；新协议下双方都从零起步，"教师更强"未必是应然；
  (d) 如果 Teacher 确实不强，选项有：给它更多 epoch（会破坏"单一协议"的说法）、
  接受并把蒸馏臂如实报告为"蒸馏一个弱教师"（内部比较仍然公平，可能也是更诚实的写法）、或削减 Teacher 的任务。
- **需要我做的判断**：**"所有臂用同一协议"与"教师必须可证明地更强"这两条原则，哪一条优先**；
  以及"提前中止 sweep"算不算破坏协议（如果算，就必须先跑完再作解释；如果不算，就必须把中止的判据写在结果里）。
